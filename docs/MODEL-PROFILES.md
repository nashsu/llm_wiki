# 独立模型档案导入

2026-10-03。薄适配，复用 Wiki 现有 custom preset、providerConfigs 和配置解析，不新增运行代理、不依赖数字分身在线。

## 操作

1. 在数字分身设置导出**已保存**的模型档案（或运行 `dws-doppelganger --model-profile-export`）。
2. Wiki 设置 → LLM → 导入模型档案，选择 JSON，核对模型、基础地址和修订，点击添加预设。
3. 在新预设中配置本地认证，使用已有连接／能力测试；成功后自行选择全局、项目或 chat/ingest 绑定。导入本身不激活、不改变任务路由或队列。

清除按钮只清除导入预览，不删除已有预设。失败有局部反馈，可重试；持久化不是跨配置项数据库事务，失败可能已注册新预设，但不会切换当前模型。重复导入同一内容幂等，同修订不同内容拒绝。

## 合同与认证边界

严格六个字段：`schema_version=1`、`profile_id`、`revision`、`protocol=openai-chat-completions`、`endpoint`、`model`。文件最多 16 KiB；身份只允许字母、数字和连字符；端点必须是无认证、查询参数和片段的 HTTP(S) 基础地址，不能是完整请求路径。未知字段、凭据、headers 和运行参数拒绝。

每个修订对应独立 custom preset；ID 使用身份长度分隔和前 16 位修订，防止身份前缀混淆。同 ID 内容冲突会拒绝，不静默覆盖。档案不携带认证：首次不继承全局 key/headers；仅相同档案身份、协议、**完全相同的端点**可复用 Wiki 本地旧修订的认证。新端点、其他身份不继承；旧预设不被改写。

凭据、视觉/向量 provider、并发、摄取超时、重试、队列全部留在 Wiki。档案含内部端点，仍不应公开发布为知识页。分身删除档案或退出不会影响已保存的 Wiki 预设。没有额外模型调用，没有双向自动同步。

## 交互与验证边界

文件读取／保存异步执行，操作中即时局部反馈、禁止重复提交；预览及反馈预留固定空间，失败保留可核对内容但禁用旧预览提交。导航不被禁用，无自动聚焦、通知或装饰性动效。

回归覆盖导入解析、非法端点／超限／秘密字段、现有配置解析、幂等、认证身份前缀隔离、只写预设与 provider 的持久化边界，以及保存失败后重试。全套 140 文件／2012 项 mock 测试通过，TypeScript、Vite 与 MCP 构建通过；真实模型测试本轮未执行。实际档案的跨应用解析已通过，未激活或修改用户模型。

桌面当前锁屏，文件选择、键盘焦点、快速点击、窗口切换、减少动态效果和视觉连续性尚未人工验收，不将静态状态检查当成 UI 通过。
