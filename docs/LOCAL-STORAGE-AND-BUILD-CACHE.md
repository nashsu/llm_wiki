## 开发缓存

体积异常主要来自 Rust 调试符号、增量缓存和多轮编译残留；旧性能录制和废弃 DMG 也已清除。源码、用户图标修改、依赖、运行的 release 应用、MCP 资源及私有验收摘要保留。

- dev/test：`debug=1` 保留行级回溯，`incremental=false` 避免增量缓存积累；release 不变。
- `build:desktop` 打包前检查指定 Rust 编译缓存，超过 6 GiB 才回收；不是应用运行时或后台删除任务，不是磁盘实时硬配额。
- `node scripts/build-cache.mjs` 仅查看；`npm run clean:build-cache` 主动回收。
- 脚本拒绝编译/debug 应用运行期间清理，拒绝符号链接和被 Git 跟踪的 target 文件，只清明确的编译目录/库。保留当前应用、执行文件、MCP 资源及 target 内独立验收材料。
- 清理后首次编译需要重建依赖，耗时会增加。自定义打包入口绕过 `build:desktop` 时，需显式先执行缓存检查。性能录制应限制时长、留摘要后手动清原始 trace，不自动清理知识或历史证据。

缓存脚本的四项本地合成测试覆盖只读、阈值、回收范围、活动编译器与符号链接拒绝，均通过；Cargo metadata 离线验证通过。本轮没有修改应用运行逻辑，无需重建 release 才能使用迁移后的数据。
