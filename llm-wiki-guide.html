安装 · 配置 · 导入 · 提问

把资料整理成
可对话的知识库

LLM Wiki 把散落的文档整理成结构化的 Wiki 页面，你用一个带引用来源的对话框，就能随时向它提问。从装好到用起来，七个步骤。

本地部署 可接 AI Agent Windows / 64 位 基于开源 llm_wiki 更新
01

安装并启动

64 位 Windows 10 / 11
第一步
  • 双击 LLM Wiki_0.6.11_x64_en-US.msi，按提示完成安装。
  • 从开始菜单或桌面图标打开 LLM Wiki。
提示：首次启动若提示缺少 WebView2，先安装微软 WebView2 Runtime，再重新打开应用。
02

创建项目

项目 = 你的知识库
第二步
  • 欢迎页点 新建项目；之后可用 打开项目 重新打开已有项目。
  • 填写项目名称。
  • 选择父目录——项目要保存到的位置。
  • 选一个模板：研究 / 阅读 / 个人成长 / 商务 / 通用。
  • 选AI 输出语言——AI 生成内容所使用的语言。
  • 点 创建。
03

配置 LLM 提供商

必须先做
第三步 · 关键

没配好 LLM，导入的资料不会被摄取，也无法对话。这一步是前提。

  • 打开左侧栏 设置 → LLM 模型。
  • 选择提供商：OpenAI、Anthropic、Google、Ollama、自定义 OpenAI 兼容等。
  • 填入对应的 API 密钥。
  • 选择（或手动输入）模型。
示例 · 接入 CVTE CCH
  • 提供商：Custom
  • API 模式：Anthropic 兼容
  • API 端点：https://token.cvte.com
  • API 密钥：填入你自己的 API_KEY
关键：每个用户的密钥需自行配置。需要免费 / 本地模型时，可用 Ollama 等本地端点。
04

导入资料

把你的文档喂进来
第四步
  • 打开左侧栏 原始资料。
  • 点 导入，选择导入文件 / 文件夹 / 网址。
  • 选中你的文档（支持 PDF、Word、Markdown、电子书等）。
提示：导入后，符合规则的文件会自动开始「摄入」。也可以直接把文件拖进项目的 raw/sources 文件夹，会被自动监听。
05

摄入：整理成 Wiki 页面

默认自动
第五步

LLM 把导入的资料整理成 Wiki 页面（实体、概念、来源等）的过程，称为「摄入」，默认自动进行。

  • 在 设置 → 资料文件夹监控，打开「监控项目资料文件夹」和「自动提取允许的原始资料文件」。
  • 导入或放入 raw/sources 的允许文件，会自动进入摄取队列开始摄入。
  • 在「摄取队列」可看到每个任务的实时阶段与进度。
手动单点：到 原始资料，选中某个文件，点「提取到 Wiki」即可手动触发。
06

用对话提问

带引用来源
第六步
  • 摄入完成后，打开左侧栏 对话。
  • 在输入框问你的知识库相关问题，回车发送。
  • 答案会附带引用来源，点引用可跳转到对应 Wiki 页面核对。
  • 回答里蓝色下划线的 路径 / 页面名 也可点击，直接打开对应页面。
进一步 · 把外部 AI Agent 接进知识库
  • LLM Wiki 提供本地 HTTP API + MCP Server + AI Agent Skill，可把 Claude Code / Codex 这类 Agent 接进来查询知识库。
  • 在 设置 → API + MCP 中开启 API、生成 Token，并按需选择是否允许本机无鉴权访问。
  • 安装配套的 agent skill（单独维护在另一个仓库），装进 Claude Code / Codex / 任意兼容 skills 的 runtime：
    npx skills add https://github.com/nashsu/llm_wiki_skill.git --skill llm-wiki
  • 装完后，Agent 就能响应如「我的 LLM Wiki 里关于 X 是怎么说的」等请求——直接调用本机运行的 App，默认只读，引用 wiki 页面路径方便你在 App 内核对。

触发约束：刻意不会响应「搜我的笔记」「看我的 Obsidian / Notion / Logseq」这类泛指请求——只有你明确说 LLM Wiki / 我的 wiki / 我的知识库时才会被调用。

团队使用

多用户协作方案
第九步 · 协作

LLM Wiki 支持多种团队协作方式，从简单的项目共享到完整的服务器部署，让团队成员能够共同使用和维护知识库。

📦 项目导入/导出共享
位置：设置 → 维护 → 项目数据

功能：
  • 导出项目为 .llmwiki.zip 文件
  • 团队成员可以导入这个ZIP文件到自己的应用中
  • 支持重建Wiki索引，确保项目完整性
适用场景：
  • 知识库的定期同步和备份
  • 团队间的知识库传递和分享
  • 跨设备迁移和灾难恢复
云同步方案：
坚果云 / Dropbox / OneDrive 同步：
1. 将项目文件夹放入云同步目录
2. 每个团队成员安装同步客户端
3. 设置定时自动导出或手动导出更新
4. 团队成员定期导入最新版本
注意：多人同时编辑可能产生冲突，建议约定更新周期
🌐 服务器部署 + API 访问
架构：在一台服务器上运行 LLM Wiki，团队成员通过网络访问

配置步骤：
  1. 在服务器上安装并运行 LLM Wiki
  2. 启用局域网访问：设置 → API + MCP → 允许局域网访问
  3. 生成API Token（或启用无认证访问）
  4. 获取服务器IP地址，分享给团队
团队成员访问方式：
  • 直接HTTP访问：通过API直接查询知识库
  • MCP客户端：AI助手通过MCP协议访问
  • Skill集成：Claude Code等Agent通过Skill访问
核心优势：
无需本地运行：
团队成员不需要在本地安装运行 LLM Wiki 应用，通过 API + MCP + Skill 就能让各种AI应用访问团队知识库：

• 搜索知识库内容
• 向知识库提问并获得带引用的回答
• 查看知识图谱和页面关系
• 触发深度研究和内容审查
🚀 实际应用场景
1. 小团队（2-5人）：
同一WiFi环境，一台机器运行 LLM Wiki，启用局域网访问。团队成员直接通过IP访问API，或使用简单的Web界面搜索知识库。

2. 大型团队/远程团队：
在公司服务器上部署 LLM Wiki，通过VPN或内网访问。所有团队成员连接到同一服务器，实现统一的知识管理和访问。

3. 开发团队：
通过 API + MCP 集成到开发工作流，让 AI 助手（Claude Code、Codex等）能够直接访问团队知识库，提供技术支持和代码建议。
🔒 安全建议
认证管理：
• 启用API Token认证，定期更换Token
• 避免将Token提交到代码仓库
• 根据需要选择是否允许无认证访问

网络安全：
• 局域网部署相对安全，但仍需注意内部网络安全
• 服务器部署建议配置HTTPS和防火墙规则
• 监控访问日志，及时发现异常访问

数据备份：
• 定期导出项目文件作为备份
• 重要知识库建议多处备份
• 制定灾难恢复计划
团队协作最佳实践：根据团队规模和需求选择合适的方案。小团队推荐局域网共享，大团队推荐服务器部署。无论哪种方案，都建议建立明确的知识库维护规范和更新机制。

补充说明

王锦 · 13 个提交 · 2026-08-25 ~ 09-30

本项目基于开源仓库 github.com/nashsu/llm_wiki 进行了更新，详细文档可去开源项目查看。改动集中在两块：一是飞书 / Jira 集成三个独立模块，二是编辑器、视图与维护体验的成批增强。

按提交时间倒序排列，下面是全部新增与增强项。

集成模块（飞书 / Jira）
飞书通知与机器人应答
AI 回复后可把内容作为简略回答发到飞书（私聊 open_id 或群聊 chat_id）。开启「飞书遥控对话」后，在飞书里给 bot 发消息，应用用与聊天界面完全相同的 AI 链路应答并回发——不碰 HTTP API、不加 token 假设；飞书会话以 feishu_{chat_id} 隔离，与前端 UI 会话互不干扰但天然支持多轮；lark-cli event consume 常驻单例、读取阻塞在 websocket 上 CPU 占用≈0；Windows 下用 taskkill /T /F 整树终止，防止 event _bus 孤儿子进程占住长连接导致下次连不上。
飞书文档发布
回复升级为文档发布，三种模式：新建（可指定飞书目录）/ 覆盖固定文档 / 追加问答日志，两级用户身份策略。mermaid 代码块自动转 mermaid.ink 渲染图并保留源码；单行回复防御性规整；覆盖模式自动重设标题防劫持；新文档默认组织内可编辑（link_share tenant_editable）。设置页提供 Device Flow 授权引导（生成链接 / 完成登录）与测试目录、测试文档按钮。聊天通知与机器人行为对齐：开文档开关发链接，关闭则发完整原文（去掉 200 字摘要截断）。
Jira 工单视图
从内网 Jira（Server/DC，REST v2，Basic 认证）把工单抓成本地资料。搜索上 JQL 只当召回预筛，客户端 NFKC + 子串匹配才是权威判定（所以 BOX 能命中 DAB_box 收音）；narrow 查空时自动 sweep 最近窗口。导出为固定七节中文 md（顺序固定、空节写「（无）」、含 Jira wiki markup 转换），附件下载进 KEY.attachments/，覆盖同工单前弹窗确认并沿用原文件名，避免同一工单被摄取成新源。已导出列表扫目录解析文件名，不额外建索引。设置页 Jira 段自持久化，密码明文存储并给出告警。
Jira 搜索与筛选增强
搜索改为显式触发：空查询不再自动拉最近工单，点「搜索」或回车才执行，空词点搜索 = 浏览最近更新。结果条数可选 50 / 100 / 200 / 500，切换即重查。搜索维度可勾选（标题 / 关键词 / 工单号）并持久化：标题走 summary ~ 客户端匹配；关键词走全文并兜底匹配 labels；工单号自动识别 issue key（单个 issuekey =、多个 issuekey in (...)）。五维度筛选（项目 / 问题类型 / 状态 / 经办人 / 责任人）从客户端过滤升级为拼进 JQL 服务端重查；新增维度盘点请求构建全量选项池，失败静默降级；原生 select 换成自制 combobox（输入过滤如输「王」出「王锦 (12)」、键盘导航、计数显示、未分配可选可筛）；重新搜索后失效的选中值自动清理。
资料树摄入状态筛选
资料树新增摄入状态筛选（全部 / 已摄入 / 未摄入），与关键字搜索叠加生效，空态与底部计数同步区分。文件夹行新增「摄取到 Wiki」按钮，一次把目录下所有可摄入文件批量入队，不支持的格式静默跳过；预过滤补齐禁止摄取列表检查，整目录全被禁止时弹框提示，不再静默无反应。
编辑器与对话
编辑器普通对话模式
编辑页右侧对话面板在「取消选中」后进入普通对话模式，基于整个知识库问答；Enter 提交、Ctrl+Enter 换行，保留多轮上下文。回答可一键保存到聊天会话并跳转完整聊天视图。
选区对话增强
点「保存到对话」弹出命名输入框（留空用默认标题）；面板头部显示已保存对话的命名；新增「退出当前对话」按钮，解绑后可另起新对话；绑定对话后，新轮次自动存入聊天页，无需手动保存。
预览区多标签页
预览区顶部显示最近打开文件的标签条（上限 10 个）：点标签切换文件，可关闭单个 / 其他 / 全部标签；切换视图后标签仍在。聊天引用类临时预览不产生标签。
视图常驻挂载
搜索页、检查页、知识库视图与左侧面板常驻挂载：切换视图再返回不重载页面，保留阅读/编辑模式、展开分组、滚动位置等状态；检查分析可在后台持续进行。
检查页重新分析
新增「重新分析」按钮，可中途取消；扫尾全程在活动面板显示实时进度。已解决项的 wiki/raw 文件路径渲染为可点击链接，直接打开预览。
知识库辅助编辑
检查页新增辅助编辑面板：按指令整文件 LLM 重写，词级 diff 预览确认后原子应用，并自动解决对应审阅项。
会话管理
聊天会话支持收藏（置顶分组）与重命名；新增「退出当前对话」；对话页「新建对话」后直接进入行内命名输入（留空回车保留默认标题）。
搜索页资料 / 路径模式
搜索页新增「知识库 / 资料」双模式：资料模式浏览并按名称或路径实时筛选 raw/sources 目录文件；另支持按名称 / 路径筛选整个仓库文件，点击直接打开预览。
链接跳转失败提示
点击文档里的 wikilink 跳转失败时，在链接后以红色小字提示原因（数秒后自动消失）；来源卡片感叹号悬停可查看具体原因。
桌面、性能与维护
桌面悬浮窗
应用内「收起为浮窗」，支持 圆球 / 只读迷你对话窗 / 回复完成摘要胶囊 三种形态，贴屏幕右侧垂直居中；AI 回复结束时自动以摘要胶囊提醒，可一键回到完整应用。
浮窗窗口权限
补充尺寸、位置、装饰、置顶、隐藏任务栏、拖动、最大最小化等。
知识树加载优化
并发读取 wiki 元数据 + dataVersion 防抖刷新，区分「加载中 / 失败原因 / 真正为空」三种状态。
定时维护
新增定时 lint 与定时索引重建。
Source 禁止摄入
可禁止文件、文件夹被摄入；已摄入的设为禁止后，可从 wiki 移除。
来源路径标注
聊天回复标注来源路径，可点击核对；另有历史操作视图。
自定义背景图层
支持在设置中调节透明度与亮度。
文件管理器定位
在原始资料树、Wiki 文件树和知识库页面列表中，可将文件 / 文件夹在系统文件管理器中定位打开。
摄入队列增强
批量移除（仅移除已取消任务）；队列行展示实时摄入阶段；拦截时（类型不支持 / 未配置可用 LLM）弹出原因；显示单个文字的摄入进度。
